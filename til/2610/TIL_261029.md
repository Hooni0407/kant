### 2. 오늘 학습 한 내용을 나만의 언어로 정리하기
- 실무에 가서는 한번의 충돌이 엄청난 시간적 낭비를 불러 올 수 있으므로 반복 트레이닝을 통해 최대한 충돌을 피해야할 거 같다.

### <터미널 명령어>
- -b : 브랜치를 만들고(Branch), 그곳으로 바로 이동하는 명령어
- git switch 브랜치명 : 해당 브랜치로 전환
- git log --oneline -- all : 뒤에 --all를 붙이면 모든 브랜치의 로그를 볼 수 있음
- git merge 브랜치 명 : 메인 브랜치로 전환 후 입력 시 브랜치가 합쳐짐(merge)


### <vs코드 명령어>
    ※ Ctrl + k 땐 후 f : 새로운 vs코드창


### <부가 설명>
    ※ 파일 옆에 A라고 뜨는 건 Staging Area에 들어가 있는 상태라는 뜻
    ※ 깃허브 팀원 초대 방법 : setting → Access에 Collaborators에 Manage access에 팀원 추가하기 위한 Add people 클릭 후 팀원 이메일 추가하기

### 3. 학습하며 겪었던 문제점 & 에러
    - 충돌해결 체험하던 도중 충돌을 임의로 내고 해결하는 과정에서 실수로 save-as를 하지 않고 push해서 2중 충돌을 냈음
### - 내가 한 시도
    - pull 다시 시도해서 수정 후 push를 진행함. 하지만 실패
### - 해결 방법
