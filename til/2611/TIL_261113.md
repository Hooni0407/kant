# 제목 : Docker 명령어 정리 (PostgreSQL + compose)

## 1. 오늘 학습한 내용 한 문장으로 정리한다면..
```
Docker 명령을 "무엇을 움직이는가"로 나눠서 정리했다. 명령마다 이미지, 컨테이너, 볼륨, 내 폴더 중 어디를 건드리는지 보면 덜 헷갈린다.
```

## 2. 오늘 학습한 내용
#### 1. 명령 읽는 법
```bash
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 postgres:18
```
- docker  할 일 옵션 이름 순서로 읽는다.
- -d 뒤에서 실행 / --name 이름 붙이기 / -p 내컴퓨터:컨테이너 포트 연결 / -e 환경 변수
- \ 뒤에 공백이 있으면 줄이 끊겨서 오류가 난다. (invalid reference format)
#### 2. 이미지와 컨테이너
- 이미지: pull, images, rmi
- 컨테이너: run, ps, ps -a, stop, start, restart, rm
- logs --tail 3 마지막 3줄 / logs -f 계속 보기 (Ctrl+C로 종료)
- 지우는 순서: stop → rm → rmi. 켜져 있는 컨테이너나 쓰는 이미지는 못 지운다.
#### 3. 컨테이너 안에서 작업하기
- docker cp kant_shop.sql my-pg:/tmp/kant_shop.sql 파일 복사
- docker exec -it my-pg bash 들어가기 / docker exec my-pg ls /tmp 명령 하나만 실행
- #### SQL 파일 실행 방법 두 가지
    - 복사 후 psql -U postgres -f /tmp/kant_shop.sql
    - 복사 없이 docker exec -i my-pg psql -U postgres < kant_shop.sql
- < 로 파일을 넘길 때는 -it가 아니라 -i만 쓴다. (cannot attach stdin to a TTY)
    - -i는 입력을 잇는 것, -t는 터미널 화면을 잇는 것
#### 4. 볼륨
- volume create / ls / inspect / rm
- -v pgdata:/var/lib/postgresql 로 붙이면 컨테이너를 지워도 데이터가 남는다.
- PostgreSQL 18부터는 데이터 자리가 /var/lib/postgresql이다. (17까지는 /data)
- 쓰고 있는 볼륨은 지울 수 없다. (volume is in use)

#### 5. YAML과 compose
```yaml
services:
  db:
    image: postgres:18
    container_name: my-pg
    environment:
      POSTGRES_PASSWORD: admin1234
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
```
- 들여쓰기가 "누구 안에 있는지"를 정한다. 같은 단계는 칸 수를 맞춘다. (관례는 2칸)
- 탭 금지, 이름: 값 에서 콜론 뒤 한 칸 띄우기
- docker run 옵션 하나가 compose의 칸 하나에 대응한다.
```
<run>     	<compose>

--name	    container_name
-e	        environment
-p	        ports
-v	        volumes
```
compose 명령
- docker compose config             : 파일 검사 (up 전에 쳐 보기)
- docker compose up -d / ps / logs / stop / start / restart
- docker compose exec db psql ~     : 뒤에는 서비스 이름
- docker compose down               : 컨테이너만 삭제, 볼륨은 유지
- docker compose down -v            : 볼륨까지 삭제
- container_name을 안 적으면 이름이 폴더-서비스-1로 붙는다.

6. 오류 메모
```
            <오류>	                              <원인 / 해결>
container name already in use   : 같은 이름 컨테이너 존재 → docker rm 후 재실행
port is already allocated       : 5432를 이미 사용 중 → 하나 끄거나 -p 5433:5432
No such container               : compose 이름이 달라서 → docker compose ps로 확인
go-yaml load error              : 탭, 들여쓰기, 콜론 뒤 공백 → compose config로 확인
```
